## Performance comparison

Same-machine CPU kernels, three warmed samples per case, median reported. Ka = 1.1, Kb = −8. ROI 1024 × 768, view angle 17°; all cases select 786,436 source pixels. The count, sum, mean and peak match the MATLAB reference exactly. JavaScript measurements use Node.js 24.19.0 (V8); MATLAB uses R2026b. **These are not browser end-to-end timings** and exclude decoding, rendering, startup and export.

| Image | MATLAB preprocessing | JS preprocessing | MATLAB ROI + histogram | JS ROI + histogram |
|---|---:|---:|---:|---:|
| 1920 × 1080, 8-bit | 9.29 ms | 7.37 ms | 35.70 ms | 3.82 ms |
| 2560 × 2048, 8-bit | 19.33 ms | 18.89 ms | 43.03 ms | 2.68 ms |
| 4096 × 3072, 16-bit | 43.01 ms | 52.41 ms | 66.18 ms | 7.18 ms |
| 6000 × 4000, 16-bit | 80.19 ms | 109.90 ms | 106.47 ms | 4.11 ms |

The scanline ROI algorithm is faster in these cases (about 9–26×); whole-image preprocessing is not uniformly faster. Browser responsiveness benefits from moving processing into a Worker even when wall-clock compute time is similar.

The processed 4096 × 3072 16-bit buffer occupies 24 MiB versus 96 MiB for the MATLAB double buffer (75% less); for 8-bit arrays the reduction is 87.5%. These figures describe that pixel buffer, **not total application memory**. Source buffers, previews, compressed files and temporary export allocations also consume memory.

Raw timing evidence: `performance.json` and `matlab-benchmark.json`. Reproduction: `pnpm benchmark` uses the retained MATLAB baseline. A new machine requires regenerating the MATLAB timing baseline for a same-machine comparison.
